## 1. Общий подход к выполнению работы

### Что требуется сделать

Выполнить **сравнительный OSINT-анализ цифровых контуров** нескольких организаций одной отрасли. Нужно:
- Выбрать 3+ сопоставимых объекта одной отрасли
- Собрать данные по каждому объекту по **единой системе критериев**
- Построить сравнительную матрицу с аналитическими комментариями
- Визуализировать результаты (ASCII-карты контуров)
- Сформулировать отраслевые паттерны, сходства, различия и оценку цифровой зрелости

### Важное отличие от предыдущих работ

Практика 4 фокусируется не на детальной реконструкции одного контура (как практика 3) и не на поиске рискованных публикаций (как практика 2), а на **сравнительном анализе нескольких экосистем** по единым критериям.

**Ключевые различия:**

| Практика 1 | Практика 2 | Практика 3 | Практика 4 |
|---|---|---|---|
| DNS + сеть + ASN | Тех-следы + риски | Полный контур одной | Сравнение 3+ объектов |
| Глубокий анализ одного | Рисковая матрица | Классификация по уверенности | Единая система критериев |
| Карта одного контура | Публикации + вакансии | Исторический блок | Отраслевые паттерны |
| | | | Оценка зрелости |

### Рекомендуемые объекты

Для варианта 14 (технологические компании) выберите организации:
- Одной отрасли (технологические экосистемы / SaaS-платформы)
- Сопоставимого масштаба (крупные технологические компании)
- С открытой документацией и публичной инфраструктурой
- Разного глобального охвата (глобальные + региональные)

**Выбранный набор:** Яндекс (региональный лидер РФ), Google (глобальный лидер), VK (региональный лидер СНГ).

## 2. Этап 1. Постановка задачи и паспорт исследования

### Шаг 1. Выберите вариант и объект

Для варианта 14 выберите 3+ организации технологической отрасли, которые:
- Имеют разветвлённые экосистемы продуктов
- Публичную инфраструктуру (DNS, ASN, сертификаты)
- Открытую документацию и OSS-проекты

### Шаг 2. Заполните паспорт исследования

```
| Поле | Содержание |
|------|--|
| Тема | Сравнительный OSINT-анализ цифровых контуров технологических экосистем |
| Отрасль | Технологические экосистемы / многопрофильные SaaS-платформы |
| Выбранные объекты | Объект 1, Объект 2, Объект 3 |
| Обоснование выбора | Почему именно эти объекты (одна отрасль, сопоставимый масштаб) |
| Цель | Сравнительный анализ ... Выявление общих закономерностей, различий ... |
```

**Как формулировать цель (пример):**

> Сравнительный анализ цифровых контуров трёх технологических экосистем на основе открытых данных и пассивных методов OSINT. Выявление общих закономерностей, различий в структуре цифрового присутствия и признаков наблюдаемой цифровой зрелости.

### Шаг 3. Сформулируйте гипотезы

В отличие от предыдущих работ, здесь нужны гипотезы о **сходствах и различиях между объектами**, а не о структуре одного объекта:

> **Гипотеза 1:** Все три компании используют схожую архитектуру цифрового контура: основной домен → OAuth-контур → функциональные сервисные поддомены → CDN/инфраструктура.
>
> **Гипотеза 2:** Компания-лидер демонстрирует максимальную глобальную масштабируемость и степень централизации, в то время как региональные игроки имеют более локализованные цифровые контуры.
>
> **Гипотеза 3:** Облачные платформы всех трёх компаний раскрываются через отдельные доменные контуры.
>
> **Гипотеза 4:** Степень публичной документированности и открытости API — ключевой дифференциатор цифровой зрелости.

### Шаг 4. Определите единый набор критериев сравнения

В отличие от практик 1-3, здесь нужно выбрать критерии, которые будут **едины для всех объектов**:

| Критерий | Описание | Инструменты |
|---|---|---|
| Централизация доменов | Единый основной домен vs распределённая структура | DNS, whois, HTTP |
| OAuth-контур | Единая точка авторизации | OAuth docs, curl |
| Облачный контур | Выделенная облачная платформа | cloud docs, ASN |
| CDN-инфраструктура | Масштаб и архитектура CDN | CDN docs, ASN |
| Open-source стратегия | OSS-проекты и репозитории | github.com |
| Публичная документация | Уровень документирования API | docs portal |
| Инфраструктурные следы | ASN, DNSSEC, CA, IP-адресация | bgp.he.net, crt.sh |

### Что должно получиться к концу этапа

Паспорт исследования с вариантом, объектами, целью, 3–4 гипотезами и единым набором критериев.

|---|---|

**Как собирать (по шагам):**

#### Домены и DNS
1. whois → основной домен, регистратор, даты
2. dig → NS, MX, TXT, A-записи
3. crt.sh → все поддомены с сертификатами
4. HTTP-заголовки → Server, CSP, redirect

#### ASN и сеть
1. bgp.he.net → ASN, prefix originated/announced
2. ipinfo.io → IP-диапазоны, hosted domains
3. peeringdb.com → точки пиринга

#### Документация и OSS
1. Developer portal → URL документации API
2. github.com → репозитории, количество звёзд
3. Cloud docs → платформа и поддомены

#### История
1. web.archive.org → архивные версии
2. Пресс-релизы → сделки, реструктуризации

## 7. Этап 6. Построение карты контуров и визуализация

### Шаг 1. Постройте ASCII-карту для каждого объекта

Каждая карта показывает структуру цифрового контура одного объекта:

```
Основной домен
    ├── OAuth
    ├── Cloud
    ├── CDN
    ├── OSS
    ├── Docs
    ├── Media
    └── E-commerce
```

**Правила построения:**
- Центральный узел — основной домен
- Сервисные контуры — на втором уровне
- Инфраструктурные элементы — на третьем уровне
- Внешние интеграции — на четвёртом уровне
- Используйте легенду (─ прямая связь, ┈ косвенная)

### Шаг 2. Постройте сравнительную схему

Добавьте схему, на которой все три объекта показаны параллельно:

```
┌────────────────────────────────────────────────────────────┐
│        СРАВНИТЕЛЬНАЯ МОДЕЛЬ ЦИФРОВЫХ КОНТУРОВ            │
│                                                            │
│   ┌──────┐    ┌──────┐    ┌──────┐                       │
│   │ Obj1 │    │Obj2  │    │Obj3  │                       │
│   ├── OAuth    ├── OAuth    ├── OAuth                      │
│   ├── Cloud    ├── Cloud    ├── Cloud                      │
│   ├── CDN      ├── CDN      ├── CDN                        │
│   ├── OSS      ├── OSS      ├── OSS                        │
│   │            │          │                               │
│   └──────┘    └──────┘    └──────┘                       │
└────────────────────────────────────────────────────────────┘
```

### Шаг 3. Используйте легенду

```
Legend:
── → Подтверждённая связь
┈┈ → Вероятная связь
┅┅ → Внешняя интеграция
```

## 9. Этап 8. Оформление отчёта

### Структура отчёта

```
1. Титульная часть (название, дисциплина, студент, дата)
2. Паспорт исследования (таблица с вариантом, объектами, гипотезами)
3. Краткое описание отрасли (таблица функциональных блоков)
4. Карточки объектов (по одному блоку на каждый объект)
5. Сравнительная матрица (по каждому из 7+ критериев)
6. Сводная матрица (компактная таблица)
7. Карта цифровых контуров (ASCII-карты + сравнительная схема)
8. Аналитическая интерпретация (паттерны, сходства, различия, зрелость)
9. Итоговый аналитический вывод
10. Ответы на контрольные вопросы (8 шт.)
11. Рекомендуемая литература
```

### Рекомендуемый объём

10–15 страниц. Таблицы, ASCII-схемы, аналитические комментарии — без скриншотов.

## Как отвечать на контрольные вопросы

### Вопрос 1: Что такое сравнительный OSINT-анализ?

**Ответ:** Сравнительный OSINT-анализ — метод исследования, при котором цифровые контуры нескольких сопоставимых организаций анализируются по единой системе критериев, что позволяет выявить общие закономерности, различия и признаки цифровой зрелости. В отличие от описательного анализа одной организации, сравнительный подход делает доказательные выводы на основе сопоставления.

### Вопрос 2: Почему для сравнения нужно выбирать сопоставимые объекты?

**Ответ:** Сопоставимые объекты — организации одной отрасли, сопоставимые по типу деятельности, масштабу и модели цифрового присутствия. Сравнение Яндекс и Google корректно: обе — технологические экосистемы с поиском, облаком, медиа и маркетплейсами. Сравнение Яндекса и небольшого интернет-магазина некорректно — разный масштаб и модель цифрового присутствия.

### Вопрос 3: Зачем нужна единая система критериев?

**Ответ:** Единая система критериев обеспечивает равноправное сравнение. Без неё анализ превращается в последовательное описание объектов, а не сравнительный анализ. В данной работе использованы 7 единых критериев: централизация доменов, OAuth-контур, облако, CDN, OSS, документация, инфраструктура. Эти критерии применены к каждому объекту.

### Вопрос 4: Какие следы наиболее важны при сравнении цифровых контуров?

**Ответ:** Наиболее значимые следы:
- **Доменные следы** — основной домен, связанные домены, поддомены
- **OAuth-контур** — единая точка авторизации
- **Облачный контур** — выделенная облачная платформа
- **CDN-инфраструктура** — масштаб и архитектура
- **OSS-следы** — open-source проекты и репозитории
- **Документация** — уровень публичного документирования API
- **ASN/инфраструктура** — масштаб сетевой инфраструктуры

### Вопрос 5: Чем отличается описание объекта от сравнительного анализа?

**Ответ:** Описание объекта — последовательное перечисление данных по одному объекту (как в практике 3). Сравнительный анализ — сопоставление нескольких объектов по единым критериям с формулировкой выводов о сходствах, различиях и отраслевых паттернах. В сравнительном анализе каждая ячейка матрицы содержит не просто данные, а аналитический комментарий.

### Вопрос 6: Почему визуализация важна для итогового вывода?

**Ответ:** Визуализация (ASCII-карты, сравнительная схема) позволяет мгновенно увидеть масштабные различия (глобальный vs региональный), структурные сходства (OAuth → Cloud → CDN → OSS → Docs), и отраслевые паттерны (единый паттерн построения экосистемы). Без визуализации эти выводы были бы менее наглядными.

### Вопрос 7: Как различать подтверждённые и вероятные выводы?

**Ответ:** Подтверждённый вывод — основан на прямом источнике (DNS A-запись, WHOIS, публичная документация, OAuth-endpoint). Вероятный вывод — выведен по паттерну (DNS-паттерн поддомена) без прямого подтверждения. В данной работе все выводы о глобальных ASN, CDN-точках и OSS-проектах подтверждены. Выводы о внутренних сервисах и CI/CD — вероятные.

### Вопрос 8: Какие ограничения имеет исследование цифровых контуров по открытым данным?

**Ответ:** Публичные данные всегда неполны (внутренние сервисы не публичны), DNS-паттерны не заменяют прямые подтверждения, данные могут устаревать (DNS, ASN, сертификаты меняются), вакансии и блоги могут отражать устаревший стек, данные одних компаний менее публичны (VK), данные других могут быть противоречивыми (Google после 2023).

## Как отвечать на каверзные вопросы защиты

### Q1: Почему именно эти объекты выбраны?
**Ответ:** Все три — технологические гиганты с разветвлёнными экосистемами продуктов. Яндекс и VK — крупнейшие российские IT-компании с сопоставимой бизнес-моделью. Google — мировой лидер. Сопоставление позволяет выявить отраслевые паттерны и региональные особенности.

### Q2: Почему выбраны именно эти критерии?
**Ответ:** Каждый критерий отражает ключевой аспект цифровой зрелости: OAuth — централизация авторизации, облако — инфраструктурная мощность, CDN — масштабируемость, OSS — технологическая открытость, документация — уровень зрелости, ASN — сетевая архитектура, история — длительность развития.

### Q3: Как вы проверяли, что данные по разным объектам сопоставимы?
**Ответ:** Данные собирались по единой методике для всех объектов. Для каждого использовались одни и те же инструменты (crt.sh, bgp.he.net, ipinfo.io, github.com). Каждый критерий применялся к каждому объекту в одинаковой форме.

### Q4: Почему Google получил 10/10, а не просто «больше чем другие»?
**Ответ:** Оценка 10/10 основана на конкретных критериях: глобальная CDN (3 000+ точек), OSS-лидерство (Kubernetes, TensorFlow, Go), эталонная документация (developers.google.com), крупнейший ASN в отрасли (AS15169, 2.55M+ IPv4), 27+ лет эволюции, 200+ стран присутствия.

### Q5: Как вы определяли цифровую зрелость?
**Ответ:** По 6 факторам: степень автоматизации, наличие выделенных команд, длина исторической эволюции, глубина документирования, развитость OSS-экосистемы, интеграция внешних партнёров. Каждый фактор оценивался отдельно, затем синтезировалась итоговая оценка.

### Q6: Почему вы не добавили больше объектов для сравнения?
**Ответ:** Три объекта — оптимальное количество для сравнительного анализа. Больше объектов усложнило бы сопоставление, но не добавило бы новых паттернов. Яндекс и VK — два региональных лидера, Google — глобальный лидер, это покрывает все ключевые типы экосистем.

### Q7: Какие данные могли быть неполными?
**Ответ:** Внутренние сервисы (CI/CD, мониторинг) не наблюдаемы. VK публикует меньше технических деталей, чем Яндекс и Google. Данные об инфраструктуре Google после ухода из России (2023) могут быть противоречивыми. DNS-паттерны не заменяют прямые подтверждения.
