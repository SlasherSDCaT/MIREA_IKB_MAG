## 2. Основной домен и подтверждение официального статуса

### 2.1. yandex.ru — базовый домен

| Параметр | Значение | Источник |
|----------|---------|----------|
| Домен | `yandex.ru` | WHOIS (RU-CENTER-RU) |
| Создан | 1997-09-23 | WHOIS |
| Владелец | YANDEX, LLC. | WHOIS |
| NS-серверы | `ns1.yandex.ru`, `ns2.yandex.ru` | DNS |
| A-записи | 77.88.44.55, 77.88.55.88, 5.255.255.77 | DNS |
| ASN | AS13238 (YANDEX LLC) | bgp.he.net |
| DNSSEC | Включён (RRSIG + DNSKEY) | dnsviz.net |
| SPF | `v=spf1 redirect=_spf.yandex.ru` | DNS TXT |
| MX | `mx.yandex.ru` (pri 10) | DNS MX |
| HTTP-заголовки | `x-yandex-req-id`, `x-yandex-captcha`, `x-yandex-eu-request`, `portal: Home` | curl / DevTools |

**Обоснование:** Домен `yandex.ru` является основным с точки зрения истории регистрации (1997 г.) и DNS-инфраструктуры. Однако с сентября 2022 г. основной публичный вход перенесён на `ya.ru` (виртуальный/сокращённый домен), при этом `yandex.ru` сохранил все сервисные функции.

### 2.2. ya.ru — сокращённая точка входа

| Параметр | Значение |
|----------|---------|
| Домен | `ya.ru` |
| Перенаправление | 302 → ya.ru (основной портал поиска) |
| Cookie-домен | `.ya.ru` / `.yandex.ru` |
| Анти-бот | Заголовок `x-yandex-captcha: captcha` |
| ASN | AS13238 (YANDEX LLC) |

**Обоснование:** `ya.ru` используется как публичная точка входа (поиск, портал), при этом оба домена `yandex.ru` и `ya.ru` обслуживаются единой CDN и единой инфраструктурой Яндекс.

### 2.3. yandex.com — международный и OAuth-домен

| Параметр | Значение |
|----------|---------|
| Домен | `yandex.com` |
| IP | 77.88.44.55 (same pool as yandex.ru) |
| Основной сервис | OAuth (`oauth.yandex.com`) |
| ASN | AS13238 (YANDEX LLC) |

**Обоснование:** `yandex.com` функционирует как международная точка присутствия и, что критично, как OAuth-провайдер для всех продуктов Яндекса.

### 2.4. yandex.net — инфраструктурный домен

| Параметр | Значение |
|----------|---------|
| Домен | `yandex.net` |
| Основной сервис | Yandex Cloud (`cloud.yandex.net`) |
| Поддомены | `cloud.yandex.net`, `oauth.yandex.net`, `mc.yandex.net`, `*.cdn.yandex.net` |
| ASN | AS13238 + AS200350 (Yandex Cloud) |

**Обоснование:** `yandex.net` является инфраструктурным доменом для сервисов облака и мониторинга, не связан с основным порталом напрямую, но обслуживается единой сетью.

## 10. Ограничения исследования

1. **Только пассивные данные.** DNS, WHOIS, TLS-сертификаты, публичные API и документация использованы без активного сканирования.
2. **DNS-паттерны не являются доказательствами.** Поддомены по шаблонам (`travel`, `maps`, `taxi`, `navi`) не подтверждены напрямую.
3. **Вакансионные данные могут быть устаревшими.** Не все технологии из вакансий актуальны для текущей инфраструктуры.
4. **Часть контура не публична.** Внутренние сервисы, CI/CD-инфраструктура и система мониторинга частично скрыты.
5. **CSP-заголовки могут быть не полными.** Не все сервисные домены обязательно включены в CSP.
6. **Historical traces неполные.** web.archive.org архивирует не все страницы Яндекса.

## 11. Аналитический вывод

По открытым данным публичный цифровой контур Яндекса **сосредоточен вокруг основных доменов** (`yandex.ru`, `ya.ru`, `yandex.com`, `yandex.net`), **однако не исчерпывается ими**. 

Публично **подтверждены** следующие контуры:
- **OAuth-контур** (`oauth.yandex.com`) — единая точка авторизации для всех продуктов;
- **Инфраструктурный контур** (`cloud.yandex.net`, `yastatic.net`, AS13238/AS200350) — облачная платформа и CDN;
- **Медийный контур** (`dzen.ru`, `dzen.yandex.net`, `dzdcdn.net`) — выделенная медиа-платформа с отдельной CDN;
- **E-commerce контур** (`market.yandex.ru`) — самостоятельный сервисный домен;
- **Почтовый контур** (`mail.yandex.ru`, `imap/smtp`, MX, SPF, DKIM) — централизованная почтовая инфраструктура;
- **Мониторинг** (`mc.yandex.net`) — аналитический сервис Метрика;
- **OSS-контур** (`ydb.tech`, `ytsaurus.tech`, `diplodoc.tech`, `catboost.ai`) — каждый продукт с собственным доменом;
- **Публикационный контур** (`tech.yandex.ru`, `habr.com`, `infraevents.yandex.ru`) — технологический блог и конференции;
- **Карьерный контур** (`tech.yandex.ru/career`, `hh.ru`) — 600+ вакансий разработки.

**Вероятно** существуют также сервисные контуры путешествий, карт, такси и навигации по DNS-паттернам, требующие прямой проверки.

Дополнительно наблюдаются **организационные и публикационные следы**, позволяющие предположить наличие **внешних сервисных зависимостей** (GlobalSign, Google, Microsoft, Facebook, Mail.ru) и **распределённой структуры** цифрового присутствия. Часть связей подтверждена официальными источниками (WHOIS, DNS, OAuth-спецификация, OSS-репозитории), часть носит вероятный характер (DNS-паттерны) и требует дополнительной проверки.

Цифровой контур Яндекса — это **не единый домен, а сеть взаимосвязанных доменов и сервисов**, каждый из которых функционирует как самостоятельная точка входа с собственными инфраструктурными компонентами (DNS, CDN, API), но объединённых единой ASN-инфраструктурой (AS13238/AS200350).

## 12. Ответы на контрольные вопросы

### 1. Что понимается под публичным цифровым контуром организации?

Публичный цифровой контур — совокупность всех публично наблюдаемых доменных, сервисных, публикационных, кадровых, документационных и исторических следов, через которые организация представлена в цифровой среде. Это не только основной сайт, но и OAuth-платформы, облачные API, CDN, медиа-платформы, open-source проекты, почтовые и мониторинговые сервисы, технологические блоги, карьерные страницы.

### 2. Почему основной домен нельзя считать достаточным описанием?

Основной домен (yandex.ru) — лишь одна из десятков точек входа. По отдельности он не раскрывает: OAuth-контур, облачную платформу, OSS-продукты, медийный бизнес, инфраструктурные ASN, CDN и внешние интеграции. Реконструкция требует анализа разнородных источников.

### 3. Какие классы источников особенно важны?

Доменные и DNS-данные, TLS-сертификаты, ASN-реестры, публичная документация, вакансии, OSS-репозитории, CSP-заголовки, domain verification TXT-записи, архивные копии. Каждый класс раскрывает свой фрагмент: DNS — домены, вакансии — стек, CSP — доверенные сервисы, domain verification — партнёрства.

### 4. Чем подтверждённая связь отличается от вероятной?

**Подтверждённая связь** — элемент найден через прямой источник (DNS A-запись, WHOIS, публичная документация, OAuth-endpoint). **Вероятная связь** — выведена по паттерну (DNS-шаблон `*.yandex.ru`) без прямого подтверждения.

### 5. Какую роль играют help-ресурсы и документация в OSINT-анализе?

Документация раскрывает API-контур, интеграционные паттерны, SDK (Go/Python/Java/Node.js), Terraform Provider, архитектурные принципы. Каждый OSS-проект с собственным доментом (`ydb.tech`, `ytsaurus.tech`) — самостоятельная точка входа в цифровой контур.

### 6. Почему кадровые публикации полезны?

Вакансии показывают реальную организационную структуру: 600+ разработчиков, 150+ ML-инженеров, 150+ аналитиков, 200+ C++-инженеров. Раскрывают технологический стек (Go, C++, Python, Java, PyTorch, TensorFlow) — фрагмент пазла, который невозможно получить из DNS-данных.

### 7. Зачем выделять ограничения исследования?

Публичные данные всегда неполны: DNS-паттерны ≠ подтверждения, вакансии ≠ текущий стек, CSP ≠ полный инвентарь. Без ограничений выводы могут быть ошибочно интерпретированы как полные.

### 8. Почему карта цифрового контура важнее простого списка артефактов?

Карта показывает **структуру связей**: домен → сервис → инфраструктура → внешние интеграции. Список артефактов не показывает, что OAuth связывает все продукты, что CDN связывает все домены, что ASN-инфраструктура объединяет все контуры. Карта — аналитическая модель, список — инвентарь.
