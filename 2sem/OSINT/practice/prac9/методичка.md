# Методичка: выполнение практической работы № 9
## «OSINT-мониторинг изменений цифровой экспозиции и формирование индикаторов раннего предупреждения»

---

## 0. Что мы делаем и зачем

### Суть практической работы

Вы проектируете **учебную систему регулярного мониторинга** открытой цифровой экспозиции объекта. Вместо разового поиска артефактов (как в практиках 1–8) вы строите **динамическую модель**: фиксируете базовую линию, разрабатываете индикаторы изменений, собираете наблюдения, фильтруете шум и оформляете карточки предупреждений.

### Ключевые понятия

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Базовая линия** | Исходное зафиксированное состояние цифровой экспозиции | Состояние объекта на момент сбора данных (практ. 1–8) |
| **Индикатор** | Наблюдаемый признак, по которому можно обнаружить изменение | Новый домен, обновлённая вакансия, новая документация |
| **Наблюдение** | Конкретный факт изменения относительно базовой линии | Появился новый help-раздел |
| **Сигнал** | Значимое наблюдение, требующее внимания | Сигнал имеет высокий приоритет |
| **Шум** | Не значимое наблюдение (дубли, маркетинг, устаревшее) | Одна вакансия, не меняющая общую картину |
| **Карточка предупреждения** | Оформленный сигнал с описанием и рекомендацией | SIG-1: OSS-экосистема |
| **Уровень уверенности** | Насколько наблюдение подтверждено данными | Высокий / Средний / Низкий |

### Чем работа отличается от предыдущих

| Практика | Что делалось | Что мы делаем здесь |
|----------|-------------|---------------------|
| 1 | DNS + сеть + ASN — статический снимок | Что изменилось в DNS со времени базовой линии |
| 2 | Тех-следы + риски — классификация | Как меняются тех-следы (новые/старые домены, сертификаты) |
| 3 | Реконструкция контура — текущий/исторический | Какие контуры появились или исчезли |
| 4 | Сравнение 3 объектов — отраслевые паттерны | Как объект меняет экспозицию относительно себя же |
| 5 | Автоматизация — 30+ записей + классификатор | Автоматизация мониторинга — какие индикаторы можно скриптовать |
| 6 | Карта связей — 28 сущностей, 35 связей | Какие связи появились или исчезли |
| 7 | Аналитический отчёт — матрица доказательств | Какие выводы подтвердились или опроверглись |
| 8 | Сценарное моделирование — след→риск→мера | Какие сценарии материализовались |
| **9** | **Мониторинг изменений — динамическая модель** | **Базовая линия → индикаторы → наблюдения → сигнал/шум → карточки** |

## 1. Этап 1: Выбор объекта и определение границ (20 минут)

Объект — любая организация, сервис, платформа. Рекомендован **Яндекс** (вариант 6 — SaaS-сервис), так как:

- Подходит для демонстрации мониторинговой модели

### Шаг 1.2 — Заполните паспорт мониторинга

Создайте таблицу «Паспорт мониторинга»:

| Поле | Как заполнить | Пример (для Яндекса) |
|------|---------------|----------------------|
| **Вариант** | Укажите вариант задания | Вариант 6. SaaS-сервис |

### Шаг 1.4 — Проверьте границы

| Вопрос | Проверка |
|--------|----------|

## 3. Этап 3: Разработка каталога индикаторов (30 минут)

### Шаг 3.1 — Что такое индикатор

**Индикатор** — наблюдаемый признак, по которому можно обнаружить изменение. Вы должны придумать индикаторы, которые помогут отследить, что изменилось.

### Шаг 3.2 — Сформулируйте индикаторы

Для каждого индикатора определите:

| Поле | Описание |
|------|----------|
| **ID** | Уникальный идентификатор (IND-01, IND-02...) |
| **Название** | Краткое описание признака |
| **Категория** | Группа индикатора |
| **Где наблюдать** | Источник, где появится сигнал об изменении |
| **Почему важен** | Что даёт индикатор для мониторинга |
| **Порог внимания** | Когда индикатор начинает «работать» |

### Шаг 3.3 — Пример заполнения (для Яндекса)

| ID | Название | Категория | Где наблюдать | Почему важен | Порог внимания |
|----|----------|-----------|---------------|--------------|----------------|
| **IND-01** | Появление/исчезновение домена | Доменные следы | crt.sh, DNS, whois | Новые домены = расширение экспозиции | ≥1 новый домен в неделю |
| **IND-02** | Изменение DNS-записей | DNS-следы | dig NS, MX, TXT | Изменение инфраструктуры | ≥2 изменённых записи |
| **IND-03** | Изменение TLS-сертификатов | TLS-следы | crt.sh | Новый CA, новый домен в сертификате | Новый Issuer или домен |
| **IND-04** | Появление новой документации | Docs-следы | docs.yandex.net, ydb.tech | Новый сервис или API | Новая страница с HTTP 200 |
| **IND-05** | Изменение вакансий | Кадровые следы | hh.ru, career.yandex.ru | Новый стек, новые роли | ≥5 новых вакансий в категории |
| **IND-06** | Изменение OSS-контента | OSS-следы | github.com/yandex, ydb.tech | Новая архитектура, новые проекты | Новый репозиторий или docs |
| **IND-07** | Изменение HTTP-заголовков | HTTP-следы | curl, DevTools | Новый CDN, новый middleware | Изменение заголовка |
| **IND-08** | Новые публикации | Публикационные следы | tech.yandex.ru, Habr | Новый сервис или событие | Новая статья с техническим контентом |
| **IND-09** | Изменение архивных страниц | Исторические следы | web.archive.org | Появление/исчезновение | ≥1 изменённая архивная страница |
| **IND-10** | Изменение почтовых политик | Почтовые следы | DNS TXT (SPF, DKIM, DMARC) | Новая почтовая инфраструктура | Изменение политики |
| **IND-11** | Изменение верификаций | Верификационные следы | DNS TXT (google, facebook) | Новые внешние интеграции | Новая верификация |
| **IND-12** | Изменение визуальных элементов | Визуальные следы | Скриншоты, презентации | Новый бренд, новый дизайн | Новый визуальный стиль |

### Шаг 3.4 — Проверьте каталог

| Проверка | Результат |
|----------|-----------|
| ≥8 индикаторов? | 12 индикаторов |
| Каждому нужен конкретный источник? | Да, для каждого указана ссылка |
| Порог внимания конкретный? | Да, количественный или качественный |

## 7. Этап 7: Приоритизация сигналов (15 минут)

### Шаг 7.1 — Оцените каждый сигнал

Для каждого сигнала определите 6 параметров:

| Параметр | Описание | Возможные значения |
|----------|----------|-------------------|
| **Уверенность** | Степень подтверждения | Высокий / Средний / Низкий |
| **Значимость** | Влияние на экспозицию | Высокая / Средняя / Низкая |
| **Новизна** | Насколько изменение ново | Новая / Существующая / Неизвестно |

## 8. Этап 8: Карточки предупреждений (20 минут)

### Шаг 8.1 — Для чего нужны карточки

**Карточка предупреждения** — это формализованный сигнал с описанием и рекомендацией. Выбираем ≥3 наиболее значимых.

### Шаг 8.2 — Формат карточки

| Поле | Описание |
|------|----------|
| **Название** | Краткое название сигнала |
| **Описание** | Что произошло |
| **Источник** | Откуда взят |
| **Что изменилось** | Конкретное изменение |
| **Почему важно** | Влияние на безопасность/экспозицию |
| **Уверенность** | Высокий / Средний / Низкий |
| **Приоритет** | Высокий / Средний / Низкий |
| **Защитная мера** | Что можно сделать |
| **Ограничения** | Что может быть неполным |

### Шаг 8.3 — Заполните карточки (4 карточки для Яндекса)

#### Карточка SIG-1: OSS-экосистема

- **Что:** Публичная OSS-экосистема (github.com/yandex, ydb.tech, ytsaurus.tech, diplodoc.tech)
- **Источник:** github.com/yandex, ydb.tech, diplodoc.tech
- **Изменилось:** Появление новых docs-контуров (ydb.tech, ytsaurus.tech, diplodoc.tech), 65K+ звёзд на GitHub
- **Важно:** OSS-документация раскрывает внутреннюю архитектуру API, технологии, конфигурации
- **Уверенность:** Высокий
- **Приоритет:** Высокий
- **Мера:** Аудит OSS-репозиториев, pre-commit хуки, удаление внутренних примеров
- **Ограничения:** Некоторые репозитории могут быть forked ранее аудита

#### Карточка SIG-2: Вакансии

- **Что:** Масштабный набор разработчиков (600+ dev-вакансий на hh.ru)
- **Источник:** hh.ru/employer/yandex
- **Изменилось:** 150+ ML, 150+ C++, Python, Java — детализированный стек
- **Важно:** Вакансии позволяют восстановить актуальный технологический стек организации
- **Уверенность:** Высокий
- **Приоритет:** Высокий
- **Мера:** Обобщённые формулировки, исключение конкретных версий технологий
- **Ограничения:** Вакансии динамичны — информация быстро устаревает

#### Карточка SIG-3: Документы

- **Что:** Новые документации-контуров (ydb.tech, ytsaurus.tech, diplodoc.tech)
- **Источник:** ydb.tech/docs, ytsaurus.tech/docs, diplodoc.tech
- **Изменилось:** Появление 3 новых docs-платформ с подробными API-описаниями
- **Важно:** Документация может раскрывать API-эндпоинты, конфигурации, внутреннюю структуру
- **Уверенность:** Высокий
- **Приоритет:** Средний
- **Мера:** Аудит docs на предмет избыточной детализации
- **Ограничения:** Docs могут быть публичными по дизайну (не ошибка)

#### Карточка SIG-4: TLS-индикатор

- **Что:** Использование внутреннего CA (Yandex CA) + внешний (GlobalSign)
- **Источник:** crt.sh
- **Изменилось:** Два независимых CA — внутренний и внешний
- **Важно:** Внутренний CA указывает на контроль над инфраструктурой, внешний — на публичное доверие
- **Уверенность:** Средний
- **Приоритет:** Средний
- **Мера:** Мониторинг новых сертификатов, аудит IssuerName
- **Ограничения:** Certificate transparency logs — только публичные сертификаты
